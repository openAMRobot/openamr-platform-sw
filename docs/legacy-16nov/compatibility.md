Decision this serves: on 16 Nov the current 2.0 base software runs on the working v0.0.1
platform. The Teensy keeps reading the external encoders and driving the existing motors and
drivers. Scope: operator UI, manual driving, ROS 2 and Nav2, LiDAR, odometry and localization,
navigation goals, cancellation, software Stop and Resume. Out of scope: arms, lift, infrared,
ultrasonic and ToF sensors.

The host-side changes proposed here are the `legacy_v001` profile
(`ros2/src/openamrobot_bringup/launch/legacy_v001.launch.py` and
`ros2/src/openamrobot_bringup/config/legacy_v001/`) plus two opt-in arguments of
`openamrobot_nav2/launch/navigation_launch.py` (`use_waypoint_follower`,
`status_profile_path`). No default of an existing launch file changes. Firmware changes are
listed for Evans and are not made in this repository.

Abbreviations in the "Today" column: `fw` = platform-fw main overlay,
`fw/src/firmware.ino` = `boards/teensy_4_0/linorobot2_overlay/src/firmware.ino`,
`fw/config` = `boards/teensy_4_0/linorobot2_overlay/config/lino_base_config.h`,
`lino` = linorobot2_hardware `aaf9d59`, `sw` = this repository at `f71f9f1`.

## What PR #131 already covers and how this profile relates

PR #131 (night-shift draft) adds `hday_legacy.launch.py`, a commissioning-limits file and
install units. It reuses `real_bringup.launch.py` (so it inherits any TF change there) and only
passes `imu_topic:=/imu/data` if real_bringup declares it after PR #129. It keeps the waypoint
follower and uses 1.0 rad/s. `legacy_v001` differs on purpose: it owns the Gate A transforms,
sets the EKF IMU topic directly, disables the waypoint follower, names the enabled producers
for PR #90 and gives the status node a profile for this rig. The two should converge into one
profile before the session; the owners pick which. The install units of #131 are not
duplicated here.
